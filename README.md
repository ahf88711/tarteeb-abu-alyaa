# ترتيب أبو علياء

**المستودع:** https://github.com/ahf88711/tarteeb-abu-alyaa

تطبيق ويب عربي (RTL) لترتيب قائمة أسماء مختارة وفق سجلاتها التاريخية في ملف PDF رئيسي.

**الدقة والتتبع والترتيب الحتمي أهم من السرعة. لا تخمين عند الشك.**

## المعمارية

```
المستندات
  → محرك الاستخراج والتحقق (OCR / جداول / مطابقة أسماء)
  → بيانات منظمة موثقة
  → محرك الترتيب الحتمي (كود فقط — بلا LLM)
  → النتائج + شرح + تصدير
```

### محرك الترتيب (حتمي)

1. لكل شخص: تواريخ فريدة موثقة مرتبة من **الأحدث → الأقدم**.
2. المقارنة تبدأ بأحدث تاريخ لكل شخص.
3. عند أول اختلاف: **التاريخ الأقدم يتقدّم**.
4. عند التعادل: الانتقال للمستوى التاريخي التالي **للمتعادلين فقط**.
5. بلا حد أقصى لعمق التعادل أو عدد الأشخاص.
6. نفاد البيانات دون فرق → `تعادل غير محسوم بالبيانات المتاحة`.
7. تسلسلان متطابقان → `تعادل` (بلا كسر تعادل أبجدي/ترتيبي).
8. الحالة غير المحسومة تعرض مجال الموضع الممكن مع الاحتفاظ بكل علاقات السبق المحسومة.

## سياسة الدقة

- تُقرأ الصفحة بعدة معالجات مستقلة وتُحفظ اختلافات OCR بدل إخفائها.
- تُكتشف حدود الجدول هندسيًا، ويجب أن يكون الاسم والتاريخ داخل الصف نفسه.
- لا تُدمج هويتان متقاربتان تلقائيًا؛ تظهران للمراجعة.
- لا يُعتمد تاريخ OCR تلقائيًا إلا عند اتفاق قراءتين على الأقل، وثقة عالية، وارتباط هندسي مؤكد بالصف.
- تُعرض قصاصات المصدر للأسماء والتواريخ للمراجعة والتدقيق.

## التشغيل

```bash
cd tarteeb-abu-alyaa
python3 -m pip install -r requirements.txt
# macOS: يحتاج أدوات سطر أوامر Xcode لـ swiftc (OCR عبر Vision)
# Linux/Docker: يستخدم Tesseract مع حزمة اللغة العربية ara

# واجهة ويب
make serve
# أو: python3 -m app.cli serve

# سطر أوامر بدون متصفح
make demo
python3 -m app.cli rank --master data/samples/master_page3_clean.xlsx \
  --targets data/samples/targets_page3_overlap.xlsx

# إبقاء الخادم حيًا
make keepalive
```

افتح: http://127.0.0.1:8765

## الاستخدام

1. **رفع الملف الرئيسي** — PDF واحد أو عدة ملفات PDF/Excel تُدمَج في فهرس واحد.
2. **رفع قائمة الأسماء** (صورة/PDF/HEIC) أو لصق يدوي — عند وجود تظليل أصفر تُستخرج الأسماء المظللة فقط.
3. **مراجعة الأسماء** — تأكيد أو تصحيح؛ لا اعتماد تلقائي للغامض.
4. **مراجعة التواريخ** — حذف/إضافة؛ زر «اعتماد التواريخ عالية الثقة فقط».
5. **تنفيذ الترتيب** — عرض التفاصيل + تنزيل Excel / PDF.

اختصار: زر **تجربة العينات المضمّنة** يحمّل ملفات التجربة فورًا.

### Excel كملف رئيسي

## Render وDocker

يعمل OCR في Render محليًا بالكامل عبر Tesseract، دون OpenAI API أو أي خدمة OCR
خارجية. صورة Docker المبنية على Debian Bookworm تثبّت صراحةً:

- `tesseract-ocr` مع اللغتين `ara` و`eng`.
- `libheif1` و`pillow-heif` لصور HEIC القادمة من iPhone.
- خط Noto Naskh Arabic لتصدير PDF عربي صحيح.

البناء نفسه يشغّل `scripts/verify_linux_runtime.py` على صورة عربية حقيقية، ثم يشغّل
مجموعة الاختبارات كاملةً مع `RUN_REAL_OCR_TESTS=1`. أي غياب للغة العربية أو فشل
OCR أو اختبار يُفشل البناء قبل النشر. كما يشغّل GitHub Actions الصورة ويتحقق من
`/api/health` و`/api/capabilities`، ثم يبدأ Render النشر بعد نجاح فحوص CI وفق
`autoDeployTrigger: checksPass` في `render.yaml`.

للتشغيل يدويًا:

```bash
docker build -t tarteeb-abu-alyaa .
docker run --rm -p 8765:8765 -e PORT=8765 tarteeb-abu-alyaa
```
